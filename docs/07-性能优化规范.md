# 性能优化规范

## 首屏加载目标

第一版目标是在常见微信环境下快速进入首页。首屏资源尽量只包含代码、基础 UI 和少量必要音效。非必要图片、后续关卡资源延后加载。

## 包体控制原则

- 不使用重型游戏引擎。
- 不引入大型 UI 库。
- 优先 Canvas 绘制基础形状。
- 音频小而短。
- 构建产物提交前检查体积。

## Canvas 绘制策略

每帧只绘制必要内容。静态背景可后续缓存到离屏 Canvas。光线、元件和 UI 分层绘制，避免过度阴影和大面积透明叠加。

## 资源懒加载

首页只加载首页必需资源。进入游戏页后加载当前关卡资源。音效可在首次需要前预加载，但不得阻塞首屏。

## 对象池预留

光线段、触摸点、临时向量可以后续引入对象池。第一版先保持代码清晰，但模拟循环中避免大量无意义临时对象。

## 低端机降级策略

低端机可以降低阴影、减少光线辉光、关闭非必要粒子和背景动画。Debug 性能日志用于发现瓶颈，不在发布版开启。

## Debug 开关

`Debug` 模块统一控制日志。发布版本默认关闭 `logRay`、`logPrism`、`logPerformance`。不得把大量 console 输出带到正式版。

## 帧率目标

理想目标 60 FPS，低端机最低目标 30 FPS。单帧光线模拟事件数设置上限，避免异常关卡导致卡死。
