# 多对话协作说明

## 总控对话

总控对话负责规划版本目标、拆分任务、确认优先级和合并结论。所有阶段性决策必须回填到 docs 或 prompts。

## 架构对话

架构对话负责目录结构、依赖边界、平台隔离、构建方式和代码质量。产出回填到 `docs/03-技术架构设计.md` 和工程骨架。

## 玩法对话

玩法对话负责光线传播、镜子反射、三棱镜分光、目标命中和胜利条件。产出回填到 `docs/02-核心玩法设计.md` 和 `minigame/src/rules/`。

## UI 对话

UI 对话负责首页、关卡选择、游戏内 HUD、胜利弹窗、设置页。产出回填到 `docs/04-UI视觉规范.md` 和 `minigame/src/ui/`。

## 音效对话

音效对话负责音效清单、资源限制、触发事件、静音策略。产出回填到 `docs/05-音效设计规范.md` 和 `minigame/src/audio/`。

## 关卡对话

关卡对话负责关卡数据、教程关、难度曲线和验收。产出回填到 `docs/06-关卡设计规范.md` 和 `minigame/src/levels/`。

## 性能对话

性能对话负责包体、首屏、帧率、低端机降级和 Debug 策略。产出回填到 `docs/07-性能优化规范.md`。

## 审核上线对话

审核上线对话负责 AppID、隐私、素材版权、体验版测试和发布检查。产出回填到 `docs/08-微信小游戏上线清单.md` 和 `docs/09-审核风险清单.md`。

## Codex 指令对话

Codex 指令对话负责把下一步开发任务写成可执行 prompt，放入 `prompts/`。每个 prompt 应包含目标、范围、验收标准和禁止事项。

## 内容如何回填 GitHub

任何对话的结论都不能只留在聊天记录里。文档结论进入 `docs/`，开发任务进入 `prompts/`，代码实现进入 `minigame/src/`，归档原型进入 `archive/demo/`。每轮完成后提交 Git commit，方便 GPT 和人工审查。
