# 《折光回廊》Codex 协作规则

## 1. 基本协作规则
- 每次只做一个阶段。
- 不要一次性创建完整游戏。
- 不要擅自加入剧情。
- 不要改成 PC 游戏。
- 不要引入键鼠操作。
- 不要提前做广告、登录、云排行榜。
- 不要提前实现分光机制。
- 游戏代码阶段开始前，必须先读取 `docs/00_project_brief.md` 到 `docs/10_risks_and_decisions.md`。
- 每次提交前必须自检禁止项。

每次完成后必须输出：
- 分支名
- commit hash
- 修改文件列表
- 变更摘要
- 待确认问题
- 是否违反禁止项

## 2. 提交前自检清单
- 本次工作是否只覆盖当前阶段目标。
- 是否混入非微信小游戏方向的交互描述。
- 是否擅自新增未批准机制。
- 是否统一使用正式术语。
- 是否完成全文禁止项搜索。

## 3. 分支策略
- `main`：只放已审核内容
- `docs/*`：文档分支
- `feat/*`：功能实现分支
- `fix/*`：修复分支

## 5. 协作输出模板
- 分支名：当前工作分支
- commit hash：本次提交哈希
- 修改文件列表：本次新增、删除、修改的文件
- 变更摘要：本次完成了什么
- 待确认问题：需要下一阶段确认的事项
- 是否违反禁止项：明确写“否”或列出问题
